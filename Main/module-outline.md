## Module Learning Outcomes

After completing this module, learners should be able to:

1. Explain what AI is and how it differs from traditional programming.
2. Distinguish AI by capability and by approach.
3. Describe the AI workflow and evaluate a model with simple measures.
4. Explain symbolic, connectionist and behaviorist AI and give an example of each.
5. Identify real-world applications of AI and the human oversight they need.
6. Recognise limitations and ethical concerns, including bias, privacy, hallucination and regulation.

## Standard Chapter Template (V2.0)

Every Stage 2 chapter has the same structure.

| Part | Content |
| ---- | ------- |
| Header | Title, **Audience**, **Estimated time**, **Format**, line, Table of Contents, line |
| Learning Outcomes and Where This Chapter Fits | What the learner will do; links to earlier and later chapters |
| Numbered sections | Each starts with an everyday "Start with a question", then **In plain words**, then the technical definition, a worked example and a figure |
| Pause and predict | Short in-text prediction with a "Check" answer |
| Two missions | Guided activities with Goal, Preparation, Task, Observe, Reflect, Feedback |
| Common Misconceptions | Table of wrong ideas and corrections |
| Quick Check | Seven questions (true/false, multiple choice, short answer) |
| Summary, Connections and Reuse | Key takeaways; links to other chapters; how the chapter feeds the Study Guide, Test Bank, PPT and Video |
| Answer Key | Answers to missions and quick check |
| Glossary | Every new term |
| References | Numbered references with links |

## Writing Principles Used in Every Chapter

1. **Plain first, formal second.** Every new term gets a one-sentence plain explanation before the official definition.
2. **Short sentences** and a formal but simple university tone.
3. **Everyday example before technical example.**
4. **Hard ideas in steps**, with a diagram or a trace table.
5. **Every analogy has a "where the analogy breaks" note.**
6. **Missions are easy and short** (10 to 15 minutes), checked by answer keys.
7. **All figures are image files**, not Mermaid or other code-generated diagrams.
8. **PDF-friendly:** no collapsible sections or features that only work on GitHub.
