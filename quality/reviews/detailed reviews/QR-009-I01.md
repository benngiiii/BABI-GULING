## 3. Review Findings and Suggested Improvements

### Finding 1: Module-Level Learning Outcomes Are Missing

**Severity:** Medium

**Observation:**

The supplied Module Outline lists chapter topics, prerequisites, planned activities, and development status, but it does not explicitly state the learning outcomes for the module as a whole.

Without these outcomes, it is difficult to determine how the five chapters collectively support the intended learning goals or how the planned activities assess those goals.

**Suggested Improvement:**

Add a concise section titled **Module Learning Outcomes** describing what learners should be able to do after completing the module.

The outcomes should be consistent with the separate Project Plan. They should cover the intended introductory understanding of AI, its classifications and processes, its applications, and its limitations or ethical concerns, to the extent specified by the team's agreed curriculum.

Avoid adding new outcomes that have not been agreed upon by the team.

### Finding 2: Development Status Labels Need Clearer Definitions

**Severity:** Medium

**Observation:**

The document defines four labels: Outline only, Drafted, Checked, and Needs revision. However, it does not explain the evidence required to assign each status.

For example, the difference between a chapter being drafted and being checked is not defined. The table also does not identify who verified the current status or when the verification occurred.

All five chapters are currently marked **Outline only**, while the known gaps state that sources remain unchecked and Chapters 4 and 5 are still planned.

**Suggested Improvement:**

Define each status using observable criteria. For example:

* **Outline only:** The chapter structure and planned topics exist, but substantive explanations are not yet developed.
* **Drafted:** Substantive content has been written, but it has not completed the required review.
* **Checked:** The content has been reviewed against agreed quality criteria, and the review outcome is recorded.
* **Needs revision:** A review has identified unresolved issues that require correction.

Add a verification date and responsible person if practical. Change a chapter's status only when its actual Markdown file supports the change.

If the team needs to distinguish between a drafted chapter, a reviewed chapter, and a chapter awaiting corrections, keep the labels and definitions consistent throughout the Module Outline and related tracking documents.

### Finding 3: Stage 1 Targets Do Not Identify the Selected Developed Topic

**Severity:** High

**Observation:**

The Stage 1 Target column marks Chapters 1–3 as "Draft" and Chapters 4–5 as "Outline." However, the outline does not identify which specific topic will serve as the substantively developed Markdown topic for Stage 1.

The chapter-level targets also do not show whether the selected topic contains the explanations, terminology, example or demonstration, appropriate visual where useful, learner activity, explained answer or expected outcome, and references required for the developed content.

The current status table does not establish that any chapter or topic has met those requirements.

**Suggested Improvement:**

* Identify the selected Stage 1 developed topic.
* Confirm its actual development status against the Markdown file.
* List the essential components that must be present for it to qualify.
* Record any missing components and the work needed to complete them.
* Keep the remaining chapter targets realistic and distinguish planned work from completed work.

The selected topic should be chosen based on actual content and readiness rather than the Stage 1 Target label alone.

### Finding 4: Chapter-Level Status Is Too Broad to Track Individual Sections

**Severity:** Medium

**Observation:**

The status table assigns one current status to each entire chapter. This is useful for a high-level overview but may hide differences between sections within the same chapter.

For example, a chapter may have one developed example and several sections that remain outlines. The current table cannot represent that difference.

The Stage 1 requirements also call for clear development-status information for the learning content.

**Suggested Improvement:**

Retain the existing five-chapter summary, but add or link to a more detailed status table identifying important sections or topics, their current status, and remaining work.

The more detailed table should reflect the actual chapter files. It should not imply that every section in a chapter has the same level of development unless that has been verified.

Keep this section-level tracking in the Module Outline rather than duplicating the complete task list from the Master Task List.

### Finding 5: Planned Activities Need More Specific Learning Outcomes and Answer Expectations

**Severity:** Medium

**Observation:**

The Planned Examples and Activities table provides a useful activity for each chapter. However, some descriptions remain broad.

For example, Chapter 2 asks learners to sort real products into AI types without specifying the intended categories or how ambiguous examples will be handled. Chapter 3 mentions a workflow diagram but does not state what learners should demonstrate. Chapters 4 and 5 explicitly indicate that their activities remain to be developed.

The supplied outline also does not confirm that the activities include answers, explanations, or expected outcomes.

**Suggested Improvement:**

For each planned activity, briefly identify:

* The concept or learning outcome being assessed.
* What learners must do.
* The expected answer, result, or explanation.
* Whether an answer key or teacher guidance still needs to be developed.

For Chapter 2, use classification categories consistent with the actual chapter content. Avoid presenting the categories as mutually exclusive if the curriculum explains that different classification perspectives can overlap.

For Chapters 4 and 5, keep the activities marked as planned until the actual materials are developed.

### Finding 6: Source Collection and Verification Need a Trackable Process

**Severity:** Medium

**Observation:**

The Known Gaps and Uncertainties section states that sources for all chapters are still being collected and have not yet been checked.

This is transparent, but the outline does not identify the intended source-verification process or show which chapters have verified references.

The outline alone therefore cannot demonstrate that the planned learning content will meet the project's source-verification expectations.

**Suggested Improvement:**

Add a short note or reference to the team's source-verification process. Track source status at the chapter or topic level, including which references have been checked and who completed the check.

Do not mark sources as verified until they have actually been reviewed. Where appropriate, prioritize authoritative sources for definitions, technical explanations, and claims about AI capabilities.

The detailed source list can remain in the relevant chapter files; the Module Outline only needs to summarize or point to their verification status.

### Finding 7: Chapter Scope Should Be Consistent with the Project Plan

**Severity:** Medium

**Observation:**

The supplied Module Outline uses concise topic descriptions, while the separate Project Plan describes more detailed subtopics.

For example, the Project Plan describes Chapter 2 using four complementary perspectives: capability, functionality, Machine Learning, and Generative AI. The Module Outline's shorter description mentions Narrow AI, General AI, Machine Learning, Generative AI, and how the types relate, but does not explicitly name the functionality perspective or the four commonly discussed functionality categories.

The Module Outline may be intentionally concise, so this difference does not automatically establish a curriculum error. However, it creates a risk that the two planning documents describe different intended scopes.

**Suggested Improvement:**

Compare the Module Outline with the current Project Plan and confirm that the main topics and intended learning outcomes agree.

Where needed, expand the Chapter 2 topic summary to reflect the agreed curriculum. The Module Outline does not need to reproduce every subsection from the Project Plan, but it should not omit a major agreed topic in a way that makes the scope ambiguous.

Apply the same consistency check to the other chapters.

### Finding 8: Chapter Ownership Uses Short Names Only

**Severity:** Low

**Observation:**

The Author column uses first names only: Jonathan, Gandhi, Benedict, Brian, and Joseph.

These names may be clear to team members, but the document may be less clear to an external reader, particularly if the README or Submission Report uses full names and GitHub usernames.

**Suggested Improvement:**

Consider using the team members' full names or a consistent author identifier that matches the README and submission documentation.

If GitHub usernames are required for identifying contributions, they can be recorded in the README or contribution evidence rather than adding unnecessary detail to every table.

### Finding 9: Known Gaps Section Contains Unnecessary Empty Space

**Severity:** Low

**Observation:**

The Known Gaps and Uncertainties heading is followed by several blank lines before the bullet list begins.

This does not affect the substantive content but may create unnecessary whitespace when rendered.

**Suggested Improvement:**

Remove the excess blank lines and retain a single readable list under the heading.

## 4. Recommended Revisions

Before the next review, the team should:

1. Add module-level learning outcomes consistent with the agreed curriculum and separate Project Plan.
2. Define the development-status labels using observable criteria.
3. Identify the selected Stage 1 developed topic and verify its actual content.
4. Keep the chapter-level summary and add or link to section-level development tracking.
5. Clarify what learners are expected to do in each planned activity and what answer or outcome should be provided.
6. Establish a trackable process for verifying chapter references and record the actual verification status.
7. Compare the Module Outline with the Project Plan to ensure their intended chapter scopes and learning outcomes are consistent.
8. Use consistent author identifiers across project documents where practical.
9. Remove unnecessary blank lines under Known Gaps and Uncertainties.
10. Check the completed Module Outline and its links in the actual repository before submission.

The Module Outline should remain a curriculum and development-status document. It should not duplicate the detailed workflow from the Project Plan or the individual task assignments in the Master Task List.

* All five chapters are identified with clear titles and main topics.
* The chapter sequence is explained, including how introductory concepts support later application and ethics topics.
* Each chapter has a proposed Stage 1 target and a current status.
* The outline provides a planned example or activity for every chapter.
* The Known Gaps and Uncertainties section openly identifies unresolved scope, activity-development, and source-verification issues.

These elements provide a useful foundation. The recommended revisions mainly concern learning outcomes, status definitions, the selected Stage 1 topic, activity expectations, and consistency with the separate Project Plan.
