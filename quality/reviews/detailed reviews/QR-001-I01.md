## 3. Review Findings and Suggested Improvements

### QR-001-I01 — Machine Learning Explanation

* **Severity:** Low
* **Status:** Open
* **Category:** Content Accuracy and Terminology

**Finding:**

Section 1.3 explains machine learning using examples where the training data contains correct answers.

This explanation is accurate for supervised learning. However, not all machine learning approaches require labeled data.

Without a brief clarification, beginners may assume that every machine learning system learns from examples with predefined correct answers.

**Suggested Improvement:**

Add a short clarification explaining that the example specifically describes supervised learning.

**Suggested Addition:**

> This is an example of supervised learning, where a model learns from labeled data. Other machine learning approaches may learn without labeled answers.

**Acceptance Criteria:**

* The chapter clearly identifies the example as supervised learning.
* Readers are not led to believe that all machine learning requires labeled data.
* The explanation remains concise and beginner-friendly.

### QR-001-I02 — Spam Filter Score Interpretation

* **Severity:** Low
* **Status:** Open
* **Category:** Worked Examples and Answer Explanations

**Finding:**

The calculation and prediction in Question 9 are correct.

However, the explanation could clarify that the numerical score produced by the simplified spam filter is not a probability or a direct measure of prediction confidence.

The current model uses a small training dataset and simple word counts. Its numerical output should therefore be interpreted within the assumptions of the example.

**Suggested Improvement:**

Add a brief explanation of the score's meaning and limitations.

**Suggested Addition:**

> The score is not a probability or a direct measure of confidence. Since the model uses only a small training dataset and simple word counts, its predictions may not always be reliable.

**Acceptance Criteria:**

* The score is not presented as a probability.
* The limitations of the simplified model are clearly explained.
* The existing calculations and answers remain unchanged.

### QR-001-I03 — Table of Contents Navigation

* **Severity:** Low
* **Status:** Optional Improvement
* **Category:** Markdown Formatting

**Finding:**

**Acceptance Criteria:**

* The Table of Contents links navigate to the intended sections.
* The links remain usable in the intended document format.
* No changes are required if the existing links already function correctly.

### QR-001-I04 — Worked Example Alignment with the Module Outline

* **Severity:** Medium
* **Status:** Open
* **Category:** Module Alignment and Completeness

**Finding:**

The Module Outline plans a worked example comparing a rule-based program and a learning-based program solving the same task.

The current chapter explains both approaches in Section 1.3 but provides a complete worked example only for the learning-based spam filter in Section 1.5.

The existing spam filter example successfully introduces training, inference, and model limitations. However, the difference between the planned activity and the developed chapter should be addressed.

**Suggested Improvement:**

The team may choose one of the following approaches:

**Option A — Update the Chapter**

Add a short rule-based spam filter example so readers can directly compare both approaches.

**Option B — Update the Module Outline**

Revise the Module Outline to match the existing learning-based spam filter example.

Option B may be more practical for Stage 1 because the current example already explains the main learning objectives effectively.

**Acceptance Criteria:**

* The chapter and Module Outline describe consistent learning activities.
* The team agrees on whether the comparison is required.
* The existing spam filter example remains accurate and understandable.
* No unnecessary major rewrite is introduced.
