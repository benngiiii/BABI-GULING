## 3. Review Findings and Suggested Improvements

### Finding 1: Stage 1 Focus Topic Has Not Been Selected

**Severity:** High

**Location:** Section 3 — Development Status Overview and Stage 1 Focus Topic.

The plan identifies three candidate topics:

* Chapter 1: Spam-filter worked example.
* Chapter 4: Healthcare.
* Chapter 5: Bias.

However, the selected topic remains unconfirmed, and the required-element checklist has not been completed.

The assignment requires at least one coherent, substantively developed Markdown topic. Listing possible topics does not establish that a suitable topic exists or is ready for submission.

**Suggested Improvement:**

1. Inspect the actual Markdown files.
2. Select the strongest topic based on the content that already exists.
3. Record the topic, file or section, selection date, and person responsible.
4. Check the explanations, terminology, example, visual where useful, learner activity, explained answer or expected outcome, and references.
5. Record the verified result in both the Project Plan and the Submission Report.

Do not select a topic solely because the plan describes it as fully developed.

### Finding 2: Chapter 3 Numbering and Table-of-Contents Links Remain Unresolved

**Severity:** Medium

**Location:** Section 2 — Chapter 3 and the Chapter 3 numbering decision record.

The plan acknowledges that the supplied contents refer to Practice Questions section 3.16, while the listed chapter sections run from 3.1 to 3.12.

The decision record still marks the comparison, correction, and link verification as pending.

**Suggested Improvement:**

* Compare the outline with the actual Chapter 3 Markdown file.
* Determine the intended numbering.
* Correct the outline or chapter file, as appropriate.
* Check that all table-of-contents links point to the correct headings.
* Record the final decision, responsible person, date, and verification result.

The issue should remain open until the actual chapter file has been checked.

### Finding 3: Project Plan and Module Outline Have Inconsistent Development Descriptions

**Severity:** High

**Location:** Sections 2 and 3, particularly Chapters 4 and 5 and the Stage 1 Focus Topic table.

The Project Plan describes Chapter 4's healthcare topic and Chapter 5's bias topic as **fully developed**. However, the supplied Module Outline and Development Status marks Chapters 4 and 5 as **Outline only**, with their Stage 1 targets listed as Outline.

These statements may describe intended content rather than verified progress, but the documents currently give different impressions of the development state.

**Suggested Improvement:**

* Compare both documents against the actual Chapter 4 and Chapter 5 Markdown files.
* If healthcare or bias content is only outlined, change the Project Plan wording to make its planned status explicit.
* If either topic has been substantively developed, update the Module Outline only after verifying the actual file.
* Keep descriptions of planned content separate from verified development status.

Both documents should present the same status for the same topic.

### Finding 4: Proposed Task Owners and Deadlines Still Need Confirmation

**Severity:** Medium

**Location:** Section 10 — Stage 1 Task Tracker.

The task tracker is substantially more actionable than a general list of responsibilities. It includes task IDs, proposed owners, target dates, expected outputs, task status, verification, and blockers.

However, the plan explicitly states that the owners and dates are proposals requiring team confirmation. All listed tasks remain pending or unverified.

**Suggested Improvement:**

* Confirm the owner and deadline for each task with the team.
* Replace proposed values with the agreed assignments.
* Update task status when work is actually completed.
* Record verification separately from completion.
* Update blockers and expected output locations when they become known.

A task should not be marked complete simply because it has an assigned owner or a planned output.

### Finding 5: Peer-Review Outcome Has Not Yet Been Recorded

**Severity:** Medium

**Location:** Section 9 — Peer-Review Record and Section 10 — Task T4.

The plan provides a useful template for recording the topic, version, author, reviewer, review date, findings, corrections, unresolved issues, and final outcome.

However, the record remains pending, and Task T4 depends on the selection of the Stage 1 focus topic.

**Suggested Improvement:**

* Select the topic before conducting the review.
* Record the exact file or section and version reviewed.
* Document specific findings and whether each was corrected or confirmed.
* Include a commit or change reference when available.
* Record the final review outcome and the location of the completed record.

The completed record must reflect a review that actually took place.

### Finding 6: Repository Evidence and Individual Contributions Remain Unverified

**Severity:** Medium

**Location:** Section 11 — Repository Evidence and Individual Contributions.

The evidence register covers repository structure, commit history, selected changes, individual contributions, and an example of review or coordination.

The individual contribution map also correctly requires evidence from the actual repository rather than relying only on assigned team roles.

However, all evidence locations and contribution details remain pending.

**Suggested Improvement:**

* Collect the actual repository overview and relevant commit-history evidence.
* Include selected changes that demonstrate meaningful contributions.
* Map each member's contributions to identifiable files, sections, or changes.
* Record where each item is stored and who verified it.
* Ensure the Submission Report contains the required evidence rather than only linking to the repository.

### Finding 7: AI-Use Records and Personal Logs Are Still Pending

**Severity:** Medium

**Location:** Section 12 — AI-Use Documentation.

The plan distinguishes shared project AI-use records from personal logs and explains what the shared records should document.

However, the actual records, their locations, and verification details remain pending. The personal-log table also has no confirmed preparation or submission results.

**Suggested Improvement:**

* Create or collect the required shared records.
* Ensure significant AI assistance is documented, including how outputs were checked and what decisions or changes resulted.
* Add the appropriate reference to the Submission Report.
* Confirm each member's personal-log preparation and separate submission according to the Shared Assignment Rules.
* Keep personal logs out of a publicly accessible repository.

Do not treat the documentation process as complete until the records have been checked.

### Finding 8: The Submission Package Is Well Specified but Not Yet Verified

**Severity:** Medium

**Location:** Section 9 — Stage 1 Submission Plan.

The plan identifies the Submission Report, Markdown source snapshot, readable content PDF, AI-use records, peer-review record, final ZIP, and extraction test. It also specifies the required ZIP filename and explains that required evidence must be included inside the package.

This addresses a major weakness identified in the previous reviews.

However, the Submission Package Record still lists the files as pending, and the checklist remains unticked.

**Suggested Improvement:**

* Confirm the actual filename and location of every deliverable.
* Verify that the content PDF includes the current learning content, Module Outline, and development status.
* Confirm that the Markdown snapshot contains the necessary source files and supporting assets.
* Check that the Submission Report includes the required repository and contribution evidence.
* Create the ZIP using the required naming convention.
* Extract it into a separate folder and open the files to verify that they are usable.

The package should be marked complete only after the final files and extraction test have been checked.

### Finding 10: Chapter 2 Terminology Verification Is Still Pending

**Severity:** Medium

**Location:** Sections 1, 3, 10, and 15.

The revised learning outcome distinguishes capability, functionality, Machine Learning, and Generative AI as complementary perspectives. The plan also identifies a task to check the Chapter 2 terminology.

This is a useful improvement, but the verification has not been completed according to the task tracker and review-response summary.

**Suggested Improvement:**

* Record the result after checking the actual chapter.

## 8. Final Review Result

The repository evidence, peer-review outcome, AI-use records, and final submission package also remain unverified.

The next version should prioritize resolving these issues and recording actual results. Adding further planning tables is less important than completing and verifying the work already planned.
