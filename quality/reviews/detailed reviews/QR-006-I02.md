## 3. Review Findings and Suggested Improvements

### Finding 1 — Deliverable ownership and task assignments

* **Status:** PASS
* **Location:** Deliverable Ownership; Master Task List
* **Review Result:** The revised document assigns preparers, reviewers, and compilers for the major deliverables. It also includes task IDs and task-level deadlines, addressing the main structural gaps identified in QR-006-I01.
* **Further Revision Required:** No mandatory structural revision identified for this item.

### Finding 2 — Stage 1 task status consistency

* **Status:** NEEDS REVISION
* **Location:** Stage 1 Tasks; Stage 1 Submission Report, Sections 3, 6, and 10
* **Review Result:** The Master Task List shows several tasks as completed or still in progress, while the submission report describes some related documents and reviews as revised, pending, or awaiting confirmation. For example, S1-02 is still marked In Progress, S1-05 is awaiting recheck, and S1-12 and S1-13 are also In Progress. Meanwhile, the submission report refers to Master Task List v1.2 and a completed Stage 1 package.
* **Suggested Improvement:** Confirm the actual state of each task immediately before submission. Ensure that the submission report describes the same version and review state as the task list.
* **Further Revision Required:** Yes. Update the statuses and report statements to match the actual project state.

### Finding 3 — Chapter review status consistency

* **Status:** NEEDS REVISION
* **Location:** Stage 1 Submission Report, Section 6: Quality Review Summary
* **Review Result:** The report lists Chapter 4 as awaiting confirmation even though a Chapter 4 review report, QR-004-I01, has been prepared with an Approved — Pass result. Chapter 2 is listed as Changes Required, while Chapter 5 is described as Pass pending final rendering verification. These entries should reflect the latest confirmed review results.
* **Suggested Improvement:** Update the Quality Review Summary to show the latest registered review IDs and outcomes. For Chapter 4, use Approved — Pass only if QR-004-I01 has been finalized and saved in the repository. Keep any genuine outstanding rendering checks visible.
* **Further Revision Required:** Yes. Synchronize the summary with the final review records.

### Finding 4 — Version references across the document

* **Status:** NEEDS REVISION
* **Location:** Version metadata; Stage 1 Submission Report, Sections 3 and 6; Revision History
* **Review Result:** The document metadata identifies the Team Project Plan and Master Task List as v1.1, but the submission report refers to Master Task List v1.2. This makes it unclear which version is being reviewed and submitted.
* **Suggested Improvement:** Confirm the intended version. If the current file is v1.1, update the submission report to v1.1. If the document has actually been updated to v1.2, revise the version metadata and revision history accordingly.
* **Further Revision Required:** Yes. Make the version references consistent.

### Finding 5 — Repository evidence links

* **Status:** NEEDS REVISION
* **Location:** Stage 1 Tasks, particularly S1-06 to S1-11; Stage 1 Submission Report, Sections 4, 8, and 10
* **Review Result:** Some links appear malformed or ambiguous. For example, the repository link in S1-06 contains an incorrect displayed URL, and several chapter links use paths without clearly showing the complete repository-relative location. The Markdown text alone does not confirm that these links resolve correctly.
* **Suggested Improvement:** Correct the repository link and use consistent relative paths to the actual files. Test each link in the rendered GitHub document.
* **Further Revision Required:** Yes. Correct and verify the affected links.

### Finding 6 — Stage 1 submission package completeness

* **Status:** NEEDS REVISION
* **Location:** Stage 1 Submission Report, Sections 9 and 10
* **Review Result:** The report lists the readable PDF and complete ZIP package as not yet produced. The submission report itself is also marked Draft. These may be acceptable if they are not required for the current submission, but they leave the package's final readiness unclear.
* **Suggested Improvement:** Check the official Stage 1 submission requirements. If the PDF and ZIP are required, produce them and verify their contents. If they are not required, label them as optional or not applicable rather than leaving the requirement unresolved. Finalize the submission report before submission.
* **Further Revision Required:** Yes. Confirm the required package contents and update the status table.

### Finding 7 — Task S1-11 scope and responsibility

* **Status:** NEEDS REVISION
* **Location:** Stage 1 Tasks, S1-11
* **Review Result:** S1-11 is described as outlining Chapters 4 and 5, but the evidence links and broader submission report describe full chapter drafts. The task's scope should distinguish between the initial outline and the later full draft so that completion can be judged consistently.
* **Suggested Improvement:** Keep S1-11 focused on producing the initial outlines. Track full chapter drafting and revision under separate tasks, or clarify which task covers the current full drafts.
* **Further Revision Required:** Yes. Clarify the scope and avoid treating an outline as equivalent to a full chapter draft.

### Finding 8 — Task status verification process

* **Status:** PASS
* **Location:** Status Labels; Ongoing Tasks
* **Review Result:** The document defines a process for confirming unverified statuses and assigns responsibility for keeping the task list updated. Ongoing tasks also cover meeting notes and peer review.
* **Further Revision Required:** No mandatory revision identified for this item.
