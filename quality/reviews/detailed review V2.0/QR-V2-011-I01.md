## 3. Review Findings and Suggested Improvements

### QR-V2-011-I01 — Findings Requiring Revision

**Finding 1: Project Plan version information is inconsistent**

**Location:** Review Information and document version/revision history.

The document is identified as Project Plan V2.0, while its submitted content still identifies its status as Version 1.4.

This creates uncertainty about whether the document has been fully updated for the current project stage.

**Required improvement:**
- Update the document's version information consistently.
- Make the document title, version status and revision history agree.
- Clearly identify the latest revision date.

**Finding 2: Learning outcomes need stronger curriculum alignment**

**Location:** Section 2 — Learning Outcomes.

The existing learning outcomes provide a general direction for the module. However, the updated curriculum requires the three classic approaches to AI to be clearly represented.

These approaches are:

- Symbolic AI.
- Connectionist AI.
- Behaviorist AI.

The Project Plan should also explain how the team's chapter structure addresses the relevant curriculum topics from PPT2024.

**Required improvement:**
- Update the learning outcomes to explicitly include the three approaches.
- Add a Course Alignment table mapping the relevant PPT2024 chapters to the team's chapters.
- Explain how the required topics are covered in the learning materials.

**Finding 3: Previous-year project analysis is not sufficiently documented**

**Location:** Course Alignment / Project Development Planning.

The lecturer's feedback requires the team to study PPT2024 and at least three previous-year projects covering symbolic, connectionist and behaviorist AI.

The Project Plan should document what the team learned from these examples and how those findings influenced the current module design.

**Required improvement:**
- Include a table for the three previous-year project categories.
- Record the relevant project or example, what the team learned and what was changed in the current content.
- Attach or reference actual evidence of the review.
- If the review has not yet been completed or evidence is unavailable, clearly state "To be completed".

**Finding 4: Chapter descriptions require updating to match the latest structure**

**Location:** Section 2 — Shared Markdown Content / Chapter Descriptions.

The original Project Plan documents the five-chapter structure from the earlier development stage.

However, the current project has expanded to eight chapters.

The Project Plan must therefore reflect the latest structure:

1. Introduction to Artificial Intelligence.
2. Types of Artificial Intelligence.
3. How Artificial Intelligence Works.
4. Symbolic AI: Intelligence from Rules and Logic.
5. Connectionist AI and Big Data.
6. Behaviorist AI: Learning by Acting and Getting Feedback.
7. Applications of Artificial Intelligence.
8. AI Ethics, Risks and Limitations.

**Required improvement:**
- Update the chapter descriptions from the original five-chapter structure to the current eight-chapter structure.
- Include the current chapter authors.
- Explain the learning progression between chapters.
- Ensure the descriptions match the latest Module Outline and actual Markdown files.

**Finding 5: Development status records need to reflect current project progress**

**Location:** Section 3 — Chapter Development Status.

The existing development-status records are useful for documenting earlier work. However, the Project Plan must distinguish between completed Stage 1 activities and the current Stage 2 development.

**Required improvement:**
- Update the status of all eight chapters.
- Distinguish completed, in-progress and pending activities.
- Reference the latest review records and supporting evidence.
- Avoid presenting older verification records as confirmation of the latest versions.

**Finding 6: Learning-resource planning needs to reflect the six Stage 2 deliverables**

**Location:** Sections 4–8 — Learning Resources and Resource Integration.

The Project Plan contains separate planning sections for the Study Guide, Test Bank, PPT Slides, Video Tutorials and Live Mini Lecture.

However, the current Stage 2 assignment defines six main deliverable groups:

A. Markdown Content V2.0 ZIP.

B. Study Guide and Test Bank.

C. PPT Slides.

D. Video Tutorials and Video Guide.

E. Project Log and Meeting Summaries.

F. Personal Logs.

**Required improvement:**
- Add a clear Stage 2 deliverables overview covering all six groups.
- Specify the expected output and responsible person for each group.
- Include the required file formats and submission packaging.
- Explain how each deliverable is reviewed and verified.
- Ensure that Project Logs, Meeting Summaries and Personal Logs are not overlooked.

**Finding 7: Learning-resource integration needs a clearer production and review sequence**

**Location:** Section 8 — Learning Resource Integration.

The existing document explains the relationship between the learning resources. However, the current production process requires a more explicit sequence.

The current workflow should establish Markdown V2.0 as the source of truth, followed by the production of the Study Guide and Test Bank, PPT Slides and Video Tutorials.

Quality review and revision must also be included.

**Required improvement:**
- Explain the Markdown-to-learning-resource production sequence.
- Identify which source document supports each output.
- Include quality review before final compilation.
- Explain how changes to the Markdown source are reflected in the other learning resources.

**Finding 8: Stage 2 submission requirements need more detailed acceptance criteria**

**Location:** Section 9 — Stage 2 Submission Requirements.

The original submission records provide a useful foundation, but the expanded Stage 2 assignment contains specific requirements for each deliverable.

**Required improvement:**
- Include the expected contents of each submission package.
- Specify required formats, such as editable DOCX, PPTX and actual MP4 video files where applicable.
- Include the required evidence and submission checklist.
- Identify the person responsible for final compilation and submission.
- Avoid treating a plan or script as equivalent to a completed video deliverable.

**Finding 9: Stage 3 planning is not sufficiently detailed**

**Location:** Section 13 — Timeline and Workflow.

The Project Plan identifies the three project stages and includes the overall Stage 3 deadline of 28 November 2026.

However, identifying a stage and its deadline does not provide enough information for the team to execute the work.

The plan needs to explain what the team will actually do during Stage 3.

**Required improvement:**

Add a detailed Stage 3 schedule that includes:

- Stage 3 objectives and expected outcomes.
- Individual activities and atomic tasks.
- Responsible owners and assigned reviewers.
- Start dates and deadlines.
- Milestones and internal checkpoints.
- Testing and quality review dates.
- Final deliverables and submission requirements.
- Evidence required to confirm task completion.

The schedule should also identify the critical path and potential risks that could affect the final submission.

**Finding 10: Timeline and task ownership need stronger consistency**

**Location:** Sections 10, 13 and the project schedule.

The Project Plan contains team responsibilities and a timeline. However, the planning information must be consistent with the latest Master Task List.

**Required improvement:**
- Match task ownership with the latest team responsibilities.
- Include owners, reviewers, deadlines and deliverables for major activities.
- Ensure Stage 2 activities run through 7 November 2026.
- Ensure Stage 3 planning covers activities through 28 November 2026.
- Identify internal review and testing dates before official deadlines.

**Finding 11: Quality assurance needs to cover all current deliverables**

**Location:** Section 14 — Quality Assurance and Risk Management.

The existing quality assurance section provides a useful foundation. However, quality control must extend beyond the original Markdown chapters.

**Required improvement:**
- Include review procedures for all six Stage 2 deliverable groups.
- Define how revisions and rechecks are recorded.
- Include consistency checks between Markdown, Study Guide, Test Bank, PPT and Video.
- Include verification of references, figures, links, file formats and submission evidence.
- Define how unresolved issues are tracked before final submission.

**Finding 12: Repository and evidence documentation need updating**

**Location:** Sections 11–12 — Repository Evidence and AI-Use Documentation.

The existing sections describe repository evidence and AI-use documentation. However, the current project has expanded, and its evidence records must support the latest deliverables and review activities.

**Required improvement:**
- Update the evidence list to cover all current project outputs.
- Include evidence links or clear file locations.
- Connect quality review reports with the corresponding reviewed files.
- Ensure AI-use records distinguish between AI assistance and each member's actual contribution.
- Keep shared project records and personal learning logs clearly separated.

The Content Author is requested to revise the Project Plan according to Section 4 and ensure that it matches the latest project requirements and supporting documents.
