## 3. Review Findings and Suggested Improvements

### Finding 1: Development Status Tracking — Substantially Addressed

**Severity:** Medium
**Status:** Addressed in planning; actual status verification pending

**Observation:**
Section 3 now contains a Development Status Overview, defines status labels, identifies work requiring verification, and explains that statuses must be confirmed against the actual Markdown files. This addresses the main omission identified in QR-007-I01.

However, most chapter and section entries remain marked "Verify actual status." The table therefore establishes a tracking process but does not yet demonstrate the current state of development.

**Suggested Improvement:**

* Compare each entry with its actual Markdown file.
* Update statuses only when supported by the file or review evidence.
* Distinguish an outline from a substantive draft and a peer-reviewed section.
* Record the person responsible for verification and the date of the check.

### Finding 2: Stage 1 Submission Requirements — Substantially Addressed

**Severity:** High
**Status:** Addressed in planning; completion pending

**Observation:**
Section 9 now lists the required Submission Report, Markdown source snapshot, readable PDF, self-contained ZIP, and extraction test. The checklist also includes the official deadline and the requirement to include evidence inside the ZIP rather than relying only on external links.

This is a substantial improvement over QR-007-I01.

**Suggested Improvement:**

* Keep each checklist item unticked until the corresponding file or evidence exists and has been checked.
* Confirm that the Submission Report contains the required repository URL, snapshot date, latest commit identifier, content-status summary, individual contributions, review outcome, and next steps.
* Confirm that the PDF includes the current learning content, Module Outline, and development status.
* Record the actual ZIP filename and the extraction-test result when completed.
* Confirm that the final package contains the required AI-use records and supporting assets.

### Finding 3: Repository Evidence and Individual Contributions — Addressed in Planning; Evidence Pending

**Severity:** Medium
**Status:** Partially addressed

**Observation:**
Section 11 identifies the required evidence: repository overview, commit history, selected changes, contribution summary, and a representative example of review or coordination. Section 10 also identifies where evidence is intended to be stored.

However, the plan does not yet provide actual evidence or a completed mapping of each member to specific files, sections, commits, or changes. The reference to Section 11 also does not establish that the evidence has been collected.

**Suggested Improvement:**

* Record the actual evidence filename or repository path for each evidence item.
* Map every member to their relevant files or sections and representative contributions.
* Confirm that commit records show meaningful changes and identifiable authors and dates.
* Include evidence of review or coordination rather than only a repository link or overview screenshot.

### Finding 4: AI-Use Documentation — Addressed in Planning; Records Pending

**Severity:** Medium
**Status:** Partially addressed

**Observation:**
Section 12 now specifies what the shared project AI-use record should contain, including the date, tool, prompt and output, verification process, and resulting change or decision. It also distinguishes shared project records from individual personal logs and states that personal logs must not be placed in a publicly accessible GitHub repository.

This addresses the documentation gap identified in the previous review.

**Suggested Improvement:**

* Confirm that the shared records actually exist and cover significant AI assistance used in the submitted work.
* Check that the records explain how AI-generated information was verified.
* Confirm that the Submission Report identifies significant AI assistance and points to the relevant records.
* Confirm that each member prepares and submits their personal log separately, as required by the Shared Assignment Rules.

### Finding 5: Peer-Review Record and Outcome — Partially Addressed

**Severity:** Medium
**Status:** Pending

**Observation:**
The revised plan makes a peer-review record an explicit Stage 1 deliverable and assigns the task in Section 10. The workflow also includes reviewing content and recording the outcome.

However, the supplied document does not identify the selected developed topic, the actual reviewer, the review date, the findings, or which revisions were completed. The plan therefore defines the requirement but does not demonstrate that the peer review has occurred.

**Suggested Improvement:**

* Identify the Markdown topic selected for Stage 1.
* Record the author, reviewer, file or section reviewed, review date, findings, and final outcome.
* Document which findings were corrected and which remain open.
* Include the completed review record in the submission evidence.

### Finding 6: Chapter 3 Section Numbering — Follow-Up Defined; Issue Unresolved

**Severity:** Low
**Status:** Pending

**Observation:**
The plan explicitly records the discrepancy between the Practice Questions section numbered 3.16 in the supplied contents and the unnumbered Practice Questions and Activities entry following Sections 3.1–3.12. It assigns a task to resolve the issue against the actual Chapter 3 file.

This makes the problem visible, but the intended numbering has not been established in the supplied document.

**Suggested Improvement:**

* Compare the Module Outline with the actual Chapter 3 Markdown headings.
* Decide the intended section number based on the actual chapter structure.
* Correct the outline or chapter file as appropriate.
* Check all relevant table-of-contents links after the correction.
* Record the final decision and verification result.

### Finding 7: Learning Outcome 2 — Addressed

**Severity:** Low
**Status:** Addressed

**Observation:**
Learning Outcome 2 now describes capability, functionality, Machine Learning, and Generative AI as complementary perspectives. It also asks learners to explain how the perspectives differ and overlap.

This addresses the previous concern that the classifications could be presented as equivalent or universally standardized frameworks.

**Suggested Improvement:**
No further change is required in the Project Plan at this stage. Ensure the Module Outline and Chapter 2 use consistent terminology.

### Additional Finding 8: Stage 1 Task Tracking Needs More Specific Evidence Fields

**Severity:** Medium
**Status:** Changes Required

**Observation:**
Section 10 lists the main Stage 1 tasks and marks them as pending. However, several tasks use broad evidence locations such as "Submission ZIP" or "Quality Review Reports folder" without identifying the expected filename, responsible individual, completion date, or verification result. The table also does not provide separate status and verification fields.

This limits its usefulness as an operational tracker when the deadline is close.

**Suggested Improvement:**

* Add an owner and target completion date for each task.
* Identify the expected output filename or exact repository path.
* Distinguish task completion from quality verification.
* Record blockers and final verification results for the submission package, peer-review record, and Chapter 3 numbering fix.

### Additional Finding 9: Development Status and Stage 1 Focus Topic Are Still Unconfirmed

**Severity:** Medium
**Status:** Pending

**Observation:**
Section 3 correctly states that the Stage 1 focus topic will be selected after actual development status is verified. However, the plan still lists three possible topics without identifying the final selection.

The current wording avoids claiming that any topic is complete, but it leaves the team without a confirmed target for the Stage 1 developed-content requirement.

**Suggested Improvement:**

* Inspect the actual Markdown files and select the strongest suitable topic.
* Confirm that it includes substantive explanations, terminology, a worked example or demonstration, an appropriate visual where useful, a learner activity, an explained answer or expected outcome, and references.
* Record the chosen topic and its verified status in the plan and Submission Report.
