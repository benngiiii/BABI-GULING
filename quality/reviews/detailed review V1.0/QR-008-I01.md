## 3. Review Findings and Suggested Improvements

### Finding 1: Repository Structure Is Not Clearly Explained

**Severity:** Medium

**Observation:**

The provided README excerpt does not show a clear overview of the repository's folder structure or explain where readers can find the Markdown learning materials and supporting resources.

**Suggested Improvement:**

Add a short section describing the actual repository structure and the location of important files.

For example, the section could identify:

* The README and other project documentation.
* The Module Outline.
* The Project Plan and Master Task List.
* The Markdown learning materials.
* Supporting images and other assets.

The listed paths must match the actual repository. Do not add folders or filenames that do not exist.

### Finding 2: Current Project Progress Is Not Clearly Summarized

**Severity:** Medium

**Observation:**

The provided excerpt does not clearly communicate the project's current overall progress or the main work that remains.

**Suggested Improvement:**

Add a brief progress section to the README that summarizes:

* What the team has completed.
* What the team is currently developing or reviewing.
* The major tasks that remain before the Stage 1 submission.

This section should provide only a high-level overview. Detailed development status for individual chapters belongs in the separate Module Outline, while task owners, deadlines, and individual task status belong in the Master Task List.

All progress statements must reflect the team's actual situation.

### Finding 3: Project Plan and Task List Locations Are Not Clearly Identified

**Severity:** Medium

**Observation:**

The provided excerpt does not clearly indicate where readers can locate the Project Plan and Master Task List.

**Suggested Improvement:**

Add a short section or a set of relative links pointing to these documents.

The README should briefly explain the purpose of each document:

* **Project Plan:** explains the overall approach, workflow, timeline, and division of responsibilities.
* **Master Task List:** tracks concrete tasks, responsible members, deadlines, and completion status.
* **Module Outline:** describes the learning outcomes, content structure, topics, and development status of the learning materials.

These documents should remain separate rather than having their full contents duplicated in the README.

### Finding 4: Learning Outcomes Should Be Consistent With the Module Outline

**Severity:** Low

**Observation:**

The README presents learning outcomes, including an outcome about AI capability classifications and technical approaches.

Because the Module Outline is a separate document, the README's learning outcomes should provide a concise overview rather than reproduce or independently redefine the detailed curriculum.

**Suggested Improvement:**

Compare the README's learning outcomes with those in the Module Outline. Ensure that they communicate the same intended learning goals and do not contradict one another.

Any necessary changes should be based on the actual Module Outline. The current evidence is insufficient to conclude that additional classification categories must be added to the README.

### Finding 5: Student IDs May Not Be Necessary in the Public README

**Severity:** Low — Optional Recommendation

**Observation:**

The provided team table includes student identification numbers.

**Suggested Improvement:**

Consider whether these numbers are necessary in a publicly accessible repository. The assignment requires team identification and GitHub usernames, but the reviewed instructions do not establish that student IDs must be displayed publicly.

If the IDs are not required, removing them would reduce unnecessary exposure of personal information.

This is an optional recommendation rather than a mandatory assignment correction.

## 4. Recommended Revisions

The following revisions are recommended for the README:

1. Add a repository structure section using the actual folder and file names.
2. Add links to the separate Project Plan, Module Outline, and Master Task List.
3. Include a concise and accurate summary of current project progress and remaining work.
4. Check that the README's learning outcomes are consistent with the separate Module Outline.
5. Consider removing student IDs if they are not required.
6. Check the complete README's Markdown formatting, relative links, and rendering before submission.

The README should remain an introduction and navigation page. It should not become a duplicate of the Project Plan, Module Outline, or Master Task List.
