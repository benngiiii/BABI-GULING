## 3. Review Findings and Suggested Improvements

### Finding 1 — Practice Questions and Explained Answers

**Location:** Section 3.16
**Priority:** Medium
**Status:** Partially Resolved

**Previous Finding:**

QR-003-I01 identified that several practice questions were combined into continuous paragraphs and that readable answers and explanations were missing.

**Recheck Result:**

The updated chapter now includes twelve clearly identified practice questions, Q1–Q12.

Each question is followed by a collapsible answer section using HTML `<details>` and `<summary>` tags.

The answers also include explanations, which resolves the previous content-completeness concern.

However, the Markdown inside the collapsible blocks may not render as intended.

For example:

```markdown
<details><summary>Answer</summary>
**B.** The algorithm is the recipe.
</details>
```

In GitHub-flavored Markdown, adding blank lines after the opening `<summary>` element and before `</details>` helps ensure that Markdown formatting is interpreted correctly.

This is particularly important for Q12, which contains a numbered list.

**Suggested Improvement:**

Use the following structure consistently:

```markdown
<details>
<summary>Answer</summary>

**B.** The algorithm is the recipe.

</details>
```

For Q12, include blank lines around the numbered list and the final explanation.

**Expected Result:** All twelve answers display correctly when expanded in GitHub.

### Finding 4 — Training-Based and Inference-Time Improvements

**Location:** Section 3.8 — Training vs. Inference
**Priority:** Medium
**Status:** Open

**Previous Finding:**

QR-003-I01 identified that Section 3.8 grouped fine-tuning and training from scratch with methods for improving results without retraining.

**Recheck Result:**

The updated chapter still uses the heading:

**Improving results without retraining**

However, the table includes:

* Prompting
* Retrieval-Augmented Generation (RAG)
* Tools and agents
* Fine-tuning
* Training from scratch

Fine-tuning and training from scratch involve training and therefore do not belong under a heading describing methods that avoid retraining.

**Suggested Improvement:**

Separate the table into two categories.

**Inference-Time Improvements:**

* Prompting
* Retrieval-Augmented Generation (RAG)
* Tools and agents

**Training-Based Improvements:**

* Fine-tuning
* Training from scratch

Alternatively, change the heading to *Ways to Improve AI Results* and clearly identify which methods require training.

**Expected Result:** Readers can distinguish methods that use an existing model from methods that modify or create model parameters.
